Phase 7: desktop app and hardening

A local-first AI assistant
for code and servers

Friday reads, edits, tests and commits in the projects you authorize, and diagnoses servers over SSH. You approve every change before it runs. It runs as a Linux desktop app or a local web app, with NoTokenLimit as its model provider.

What Friday does

Reading is automatic. Anything that changes files, runs commands or touches a server waits for your approval.

Edits you review

Every edit is shown as a diff. Each change can be undone, and a whole run can be rolled back, but never over edits you made since.

Test insights

Runs Vitest, Jest, node --test, pytest, Go and Playwright suites. It runs the tests related to your changes first, and it detects flaky and slow tests.

Code review

Reviews uncommitted changes, a branch or a GitHub pull request. Each finding has a file:line, a severity and a suggested fix.

Browser flows

Clicks through your local app the way a person would, and records a screenshot of every step. It can also compare before-and-after screenshots.

Memory per project

Remembers commands, decisions and procedures across conversations. Each project's memory is kept separate, and Friday shows which memories informed each answer.

Read-only databases

Postgres, MySQL and SQLite. Queries run in read-only sessions, and passwords never reach Friday.

Web research

Searches docs and changelogs, and writes research reports in which every claim cites a numbered source.

Local voice

Speaks replies with Kokoro and takes dictation with Whisper, on your CPU. The audio never leaves your machine.

Documents

Writes reports, plans and decks as PDF, Word, Excel or PowerPoint files, straight into the project.

You stay in control

There is no "always allow". The widest grant is a task permission, which ends when the task ends.

  1. Approve once, reject, or cancel. Each approval is tied to a hash of the exact action and the file state you reviewed.
  2. Stale means it doesn't run. If a file changes before the action runs, the action is dropped and Friday has to propose it again.
  3. Requests expire. An approval request that waits more than 15 minutes is never executed.
  4. Verification reports. Every task ends with a report built from Friday's own records, not from what the model claims.

Command sandbox

For untrusted code, you can run a project's commands in a throwaway Docker container instead of on your machine.

The container sees only the project folder, with credential files hidden and .git read-only. It has no network by default, no Docker socket and none of your environment variables. All capabilities are dropped, the root filesystem is read-only, and CPU, memory and process limits apply. The container is removed when the command ends.

DevOps with safeguards

Server diagnostics, logs, Docker, deployment plans and approved SSH commands, with extra checks for production.

Read-only diagnostics

Checks uptime, disk, memory, failed services, journals, listening ports, nginx -t and certificates.

Deployment plans

Each plan lists pre-checks with backups, the exact steps, risk, downtime, rollback and verification. A production command needs a recorded plan, and you type the host name to approve it.

Strict SSH

Friday ignores ~/.ssh/config, disables password and agent forwarding, and checks host keys strictly against the keys you trusted.

CI diagnosis

Finds the first real error in a failed GitHub Actions run and points at the project files it names.

Compose and dependencies

Manages only this project's containers. Recommended dependency upgrades are releases at least 14 days old, and Friday reads the release notes for breaking changes first.

Monitors and load tests

Shows the status of your health monitors, and runs k6 load tests against local or listed targets.

Desktop app

64-bit Linux, or WSL2 with WSLg. Node.js is built in.

npm install
npm run dist:desktop

This writes an AppImage and a .deb to apps/desktop/release/.

sudo apt install ./friday_*_amd64.deb

On first launch, open Friday › Show Config File, set NTL_API_KEY=, then restart the server from Settings.

Web app from source

Node.js 22.13 or newer and npm, on Linux, macOS or WSL2. There are no native modules to compile.

npm install
cp .env.example .env

Set NTL_API_KEY in .env, then run one of these:

# development: UI on http://localhost:5173
npm run dev

# production-style: http://127.0.0.1:4317
npm run build
npm start

First run

  1. Open Settings. It shows whether NTL_API_KEY is configured.
  2. Pick a model and click Use selected model.
  3. Test connection. This sends one tiny completion, the only check that confirms both your key and your plan's access to the model.
  4. Add a project by its absolute path. Friday can read inside that folder only. Broad locations such as / or your home folder are refused.

How it is put together

The desktop window is a sandboxed Chromium page with no Node.js access. It talks to a local server on a random loopback port, and every request carries a secret generated at launch, so other programs on the machine cannot drive the agent.

WhatWhere
Config (API key, model)~/.config/Friday/friday.env
Data (conversations, memory)~/.config/Friday/data/
Server log~/.config/Friday/logs/server.log

API keys are never stored in the database, sent to the browser or logged. Friday never reads credential files (.env, private keys, .ssh/, .aws/), even inside a project.
